# Agent instructions

Every change must run `yarn verify` from the repository root before you treat the work as done. Pass is exit code 0 and a final line `verify-runifly: PASS`. `yarn verify` runs the unit tests, lint, the production build, and the browser journey in `.cursor/skills/verify-runifly/`.

The `Quality scores` check fails when `yarn doctor` reports any finding, or when `yarn aislop` reports an error or a score below 96. Run `yarn doctor` and `yarn aislop` locally. Do not silence rules, exclude source files, or shrink either scan to move a number.

## react-doctor

`yarn doctor` is `react-doctor --no-score --no-supply-chain --blocking warning --yes` (react-doctor 0.9.21). `doctor.config.json` sets the same offline policy: `noScore`, `share: false`, `blocking: warning`, and supply-chain checks off. `--no-score` skips the score API. `--blocking warning` fails the command when any finding is present, so the gate uses this local run.

## aislop

`yarn aislop` is `aislop scan` (aislop 0.20.0). `.aislop/config.yml` sets `ci.failBelow` to `96` and turns telemetry off. The scan exits 1 when the score is below 96, and when an error-severity finding is present.

## Commits

Commit under your own GitHub identity, the human contributor's own account. An agent commits as the human it works for, never as a bot or tool account.

Do not add a `Co-authored-by:` trailer, a 'generated by' trailer, or any other tool trailer to a commit message.

Do not attribute work to AI tools, agents, or bots in commits, pull request titles, pull request bodies, code comments, or docs.

Never put a real name, a personal email, or other personal details of anyone in the repository, commits, or pull requests.

Before pushing, run `git log origin/main..HEAD --format='%an <%ae> | %cn <%ce>%n%B'`. The author and the committer must both be the human contributor's own GitHub identity, and the message must contain none of the trailers or attributions above.

## Pull requests

After opening or pushing to a pull request, wait until CI has finished and at least 10 full minutes have passed, then check for the GitHub Copilot review.

Respond to every Copilot review comment and every human review comment. Fix the point, or reply explaining why you disagree. Then resolve the thread. Leave no thread open.

A pull request's own changes must not break CI. A failure that already exists on `main` is not that pull request's job to fix. Say so in the pull request description.

Only report a pull request as ready once all of the above is done.
